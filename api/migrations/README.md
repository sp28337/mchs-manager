# Миграции

Alembic в асинхронном режиме: один драйвер и для приложения, и для
миграций (`postgresql+psycopg://`). Настройки — в `../pyproject.toml`,
секция `[tool.alembic]`; адрес базы берётся из `GRAFIK_DATABASE_URL`, а не
из отдельного файла.

```bash
make api-migrate                      # применить всё до головы
make api-revision m="блобы и ревизии"  # новая миграция по разнице с моделями
make api-check                         # не разошлись ли модели с базой
make api-downgrade                     # шаг назад
```

Правила, которые стоит держать в голове:

* **Автогенерация — черновик.** Alembic не видит переименований (он
  удалит столбец и создаст новый, то есть потеряет данные), не угадывает
  порядок при добавлении `NOT NULL` в непустую таблицу и не знает про
  данные. Сгенерированную миграцию читают и правят.
* **Откат обязан работать.** `downgrade` без тела — это миграция, которую
  нельзя снять с боевой базы; проверяется прогоном вниз и снова вверх.
* Имена ограничений задаёт соглашение из `grafik_api/db/base.py` — руками
  их придумывать не нужно, и отличаться от базы они не будут.
* После правки моделей сверьте перечень с `docs/legal/data-map.md`:
  столбца, которого нет в карте данных, в базе быть не должно.
