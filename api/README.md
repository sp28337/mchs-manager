# Сервер синхронизации «График 1 3»

Бэкенд к приложению, которое считает рабочее время при графике «сутки через
трое». Его работа — хранить **зашифрованные на устройстве** копии профилей и
отдавать их на другие устройства того же человека. Содержимого он не видит:
ключ выводится из пароля в браузере и на сервер не уходит.

Что это значит для кода: сервер не умеет ни сливать правки, ни разрешать
конфликты — слияние делает браузер. Подробности и доводы:

* [`../docs/sync-contract.md`](../docs/sync-contract.md) — формат, ревизии,
  конфликты, лимиты, протокол;
* [`../docs/openapi-draft.yaml`](../docs/openapi-draft.yaml) — черновик описания
  API (настоящее собирает FastAPI из схем);
* [`../docs/legal/data-map.md`](../docs/legal/data-map.md) — какие данные
  обрабатываются и на каком основании. Данных, которых нет в карте, в базе быть
  не должно.

## Как поднять

Всё окружение сразу — из корня репозитория:

```bash
make up        # postgres + api + mailpit
make logs      # журналы API
make down      # остановить
```

API отвечает на `http://127.0.0.1:8000/api/v1/healthz`, письма видны на
`http://127.0.0.1:8025`, описание API при разработке — на `/docs`.

Без Docker (нужен свой postgres, когда дело дойдёт до базы):

```bash
make api-sync  # или: cd api && uv sync --locked
make api-run
```

## Как проверить

```bash
make api-check   # ruff + black --check + mypy + pytest с покрытием
make api-fmt     # отформатировать (black)
```

То же самое прогоняет CI — [`.github/workflows/api.yml`](../.github/workflows/api.yml),
и он же собирает образ и дёргает `/healthz` внутри контейнера.

## Версии Python

В образе и в CI — **3.14**. В `pyproject.toml` стоит `requires-python = ">=3.13"`,
и это не небрежность: в контейнере, где пишется код, закрыт доступ к
`github.com`, откуда uv тянет управляемые интерпретаторы, и на 3.14 там не
собрать окружение вовсе. Синтаксиса, которого нет в 3.13, в коде нет —
за этим следит ruff (`target-version = "py313"`).

## Раскладка

```
src/grafik_api/
  main.py          сборка приложения: настройки, жизненный цикл, роутеры
  core/            настройки, журналирование, ошибки, крипто — ни от кого не зависит
  api/             ручки: HTTP и только HTTP; зависимости — в api/deps.py
  services/        правила: вызываются из теста без HTTP
  repositories/    запросы к базе: без бизнес-правил
  models/          таблицы SQLAlchemy
  schemas/         то, что приходит и уходит по HTTP
  db/              движок, фабрика сессий, базовый класс
  middleware/      request_id и запись доступа
tests/
```

Слои однонаправленные: `api → services → repositories → models`. Ручка не
трогает сессию базы напрямую, сервис не знает про `Request`, репозиторий не
решает, законна ли операция. Правило каждого слоя записано в его
`__init__.py` — там, где его и нарушают.

Пустых модулей «на будущее» здесь нет: файл появляется на том шаге, которому
он нужен. Что когда — в докстрингах слоёв.
